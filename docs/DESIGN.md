# 設計筆記

這份記下薄荷橋每個設計選擇背後的實測。數字都來自 agy 1.4.2、Windows 11，2026-10-19。

## 為什麼走官方 CLI，不走反向代理

市面上有把 Antigravity 帳號轉成 API 的反向代理，做法是冒充編輯器端、走編輯器內部的接口。薄荷橋只呼叫 Google 自己發的 `agy` 程式，跟你在終端機打字是同一條路。

## 角色卡怎麼送進去

agy 可以用 Markdown 檔定義自訂代理（`<工作夾>/.agents/agents/<名字>.md`，上半是設定、下半是系統提示），開跑時用 `--agent <名字>` 指定。橋每一則產生一個：

```
excludeDefaultComponents: true   # 拿掉 agy 內建那套寫程式的提示與工具
inheritCustomizations: false     # 不吃你全域的 GEMINI.md 規則
inheritMcp: false
tools: []
```

效果：同樣一句「早安」，預設代理的輸入約 11,900 token，自訂代理約 1,560 token（兩發的模型與題目不同，只能看量級）。從標準輸入送 `system` 事件，agy 明說不支援、會忽略，所以系統提示只能寫成代理檔。

## 為什麼歷史放代理檔、不放使用者訊息

實測一則 25 萬位元組、暗號放在最尾端的使用者訊息：模型回答「最後一行我看不到」。agy 在約 192,000 位元組處把使用者訊息切掉、塞一句「內容太長已截斷」，結果狀態**照樣是 SUCCESS**。同一份東西寫進代理檔，39 萬位元組（約 17 萬 token）頭尾暗號都答對。

所以橋的排法是：角色卡＋預設＋整段歷史進代理檔，標準輸入只送最新一則；最新一則超過 18 萬位元組時，整則挪進代理檔的 `<latest_message>`，標準輸入改送一句指路。正式版實測：25 萬位元組的最新一則，尾端暗號與最後一筆編號都答對。

命令列也不能塞（Windows 上限約 3.2 萬字元）。

## 為什麼每則開一個程序

| 跑法 | 首字中位數（Sonnet 4.6 短對話） |
|---|---|
| 每則開新程序 | 約 5.5 秒 |
| 每則開新程序、`--conversation` 續同一對話 | 約 5.7 秒（不會比較快） |
| 一個程序常駐連發 | 約 2.1 秒 |

慢的是開程序（2.5～4.7 秒），不是模型。常駐最快，但一個程序只能往後接，酒館的重新生成、編輯舊訊息都需要倒回去，agy 沒有倒帶。第一版選每則無狀態；常駐模式（偵測到「只在最後加一則」才走）列在之後。

另一個不續對話的理由：續對話時網路斷過一次，之後每一發明明有正常回覆，結果狀態都黏著 ERROR。橋判斷成敗看的是「模型回應步驟完成而且有字」，不信總狀態。

## 429 與重試

agy 遇到 429 會自己重試約 140 秒才放棄（exit code 3，stderr 一行 `AGY_ERROR: {...}`）。環境變數 `AGY_CLI_MODEL_API_MAX_RETRIES=0` 實測 8 秒就回，錯誤裡帶 `retryable:false`。橋預設 0，想讓 agy 多撐幾次就調 `maxRetries`。

## 內容過濾（0.1.1）

Google 擋下輸出時，agy 不是回錯誤，而是在 stderr 印「Your previous response was blocked by content safety filters … Generative AI Prohibited Use policy … Retries remaining: 3」，再把這句當提示叫模型重寫。這是 agy 自己的另一層重試，`AGY_CLI_MODEL_API_MAX_RETRIES=0` 管不到它，`agy --help` 也沒有關它的選項；同一段內容通常每次都被擋，結果一路等到逾時，0.1.0 因此把它報成逾時（玩家回報：900 秒後才出錯）。0.1.1 在 stderr 和 agy 的非回覆事件裡看到這句就立刻停掉 agy，錯誤歸「被內容過濾擋下」。模型自己寫出來的字（回覆步驟）不比對，免得劇情裡引用到這句也被當成過濾。最常被擋的是 Horae 的劇情摘要請求（要模型把整段劇情重述一遍）。

## 逾時與結束代碼（0.1.1）

`--print-timeout` 到了 agy 不一定自己停（玩家回報的那發就沒停），所以橋另外有一個計時器，在 `printTimeoutSec + 30` 秒時連子程序一起砍。在 Windows 上 `taskkill /F` 會讓 agy 的結束代碼變成 1——0.1.0 把這個代碼當原始錯誤附上，看起來像 agy 壞了。0.1.1 被橋砍掉的那發只說「橋在 N 秒時停掉了 agy」，不再附結束代碼；agy 自己結束、stderr 又沒留話時，才說「agy 自己中途結束了（代碼 N）」。預設上限從 300 秒調到 900 秒：某晚實測 `argon-medium` 配 4 萬 token 歷史每秒約 13 個 token，4,400 token 的回覆就要 5 分半。速度看 Google 那頭、每晚不同（26-10-20 量到 `argon-low` 短對話 36～52 tok/s，同晚也有一發首字 140 秒）。玩家狀態頁出現過的「每秒 4 個」不是出字速度：那是總時間（含回覆完成後空等到逾時）除下去的，0.1.2 的 `tokPerSec` 改成從第一個字到最後一個字算。

## 最大回覆長度（0.1.1）

agy 1.4.2 沒有輸出上限的選項；代理檔前置資料寫 `maxOutputTokens: 40` 實測照樣生出 806 token，它不認。所以橋邊收邊估：中文類字元約 1.15 字一個 token、其他字元約 4.4 個一個 token（實測 gemini-3.8-flash：中文 863 字＝729 token、英文 3,675 字元＝806 token），估到請求的 `max_tokens`（或 `max_completion_tokens`）就停掉 agy，以 `finish_reason: length` 正常收尾，已經生出的字是一則完整的回覆。`honorMaxTokens: false` 可以關掉。

思考不算（0.1.2）：agy 模型自己的思考根本不進串流——實測 argon-high 一則 862 個思考 token，串流裡完全靜默，第一個字出來前什麼都沒有。玩家說的「思考沒跑完就被切」是預設要模型寫在回覆裡的思考段（酒館的推理自動解析把它收進思考框）。橋只認 `<think>`、`<thinking>`、`<reasoning>` 三種標籤（不分大小寫），標籤裡的字不算；沒關上的標籤當作還在想。計數邊收邊算、每個字只看一次，被切在兩段之間的標籤先扣住等下一段。

## 回覆完成卻不退出、生到一半卡住（0.1.2）

玩家兩發都在 930 秒逾時，狀態頁卻帶著完整的 usage（輸出 3,961／2,653 token）。agy 只在最後的 `agent_response` DONE 與 `result` 事件附 usage，所以**推論**那兩發其實已經生完、是 agy 送完之後程式沒結束——這是推論，不是親眼看到（家裡重現不了：家裡走 Google Cloud 專案的 Vertex，玩家走另一條後端），等玩家用 0.1.2 的 `lingered` 旗標證實。0.1.1 等的是程式結束，才一路等到逾時。

0.1.2：收到 `result`（agy 的「這一輪完成」）就把回覆交給酒館，不等程式退出；agy 有 10 秒自己退（家裡量到 DONE→退出只要 0.2 秒），不退就砍、照成功收尾（`lingered: true`、`postDoneHangSec`）。只收到 DONE、沒有 `result` 時不提早回：DONE 之後可能還有第二段回覆步驟，所以等 10 秒寬限結束才收；這段時間又出字就重新算。收尾等 agy 真的退出才清它的本機對話檔（Windows 上剛砍的程序還開著檔時刪不掉），刪不掉的 5 秒後再清一次。卡住、逾時、不退出、失敗的那發，把 agy 自己的紀錄遮掉信箱、專案編號（含 agy 設定裡那個值逐字找）、權杖、玩家的 agy 權限規則，家目錄寫成 `~`（之後的路徑留著：「哪個檔被鎖」正是要看的）後留在外掛的 `logs/`（最近 5 份）。實測 agy 1.4.3 的紀錄裡沒有角色卡與對話內容。狀態頁整份輸出前也把家目錄（任何寫法、任何大小寫）換成 `~`。

另加一道保險：開始出字之後連續 `stallSec`（預設 120）秒沒有新字、或第一個字等了 `stallFirstSec`（預設 180）秒，就砍掉、同一發重送一次（`stallRetry`）。首字前放寬，因為模型可能在靜默思考（argon-high 實測首字 20～32 秒，26-10-20 晚上 argon-low 有一發 140 秒）。串流只能往後接、收不回已送的字，所以重送前先送一行「〔前一發卡住，重來〕」隔開（Cursor 橋 0.2.1 去圖重送是同一種做法）；前一發已送出完整的思考段時，重送那發開頭的思考段不轉送（酒館的推理自動解析只收訊息開頭那段，第二段思考會露在故事裡）。非串流只回第二發。DONE 之後不算卡住。

## 串流中途的錯誤（0.1.1）

0.1.0 把錯誤接在回覆文字後面（`[薄荷橋：…]`），玩家回報它出現在酒館的「思考」區——文字一旦進了回覆，就會被酒館的推理自動解析或正規表達式腳本當成內容處理。0.1.1 改送一個獨立的 `data: {"error":{"message":…}}` 事件：酒館的串流解析（`tryParseStreamingError`）會跳紅色通知，這個事件沒有 `choices`，不會加進回覆；已經生出的字照樣留著。

還沒出字就失敗時：串流請求照舊回真的錯誤碼（502 等），酒館後端會把內容原樣轉給前端；**非串流請求改回 HTTP 200 加 `{"error":{…}}`**——酒館後端遇到非串流的非 2xx 回應只把狀態文字（「Bad Gateway」）傳給前端，橋的說明會被丟掉（`src/endpoints/backends/chat-completions.js` 非串流分支），而 200 帶 `error` 會被前端照樣跳通知。代價是對其他照 OpenAI 規格寫的客戶端不標準；薄荷橋是酒館外掛，以酒館為準。

## 0.1.1 審核後補的幾件

- 過濾比對只看 agy 自己的訊息（非回覆步驟的文字、`result.error`、stderr），不看整行 JSON：`result.response` 裝的是整段回覆，0.1.0 的錯誤訊息又曾把那句英文寫進玩家的聊天紀錄，模型照抄就會被誤判。
- token 估算每段只算新收到的字、累加小數，不再每段重算全文（長回覆原本是平方成長）；全形標點（“”…—）算一個 token、表情符號算一個。只有空白時不算到上限；agy 最後帶 DONE 的那一段不觸發上限。
- 橋的計時器到點時不管之前是否已下令停止都再砍一次，並保證收尾，對話的名額不會被一個殺不掉的 agy 永遠佔著。
- stderr 比對用「上一段的尾巴＋這一段」，一句話被切成兩段也比得到。

## 本機留下的東西

每一發 agy 會在 `~/.gemini/antigravity-cli/` 留下：`conversations/<對話ID>.db`（約 400 KB）、`brain/<對話ID>/`（含完整逐字稿）、`annotations/<對話ID>.pbtxt`、`presence/<對話ID>.lock`。橋生完就刪這四樣（只刪 UUID 格式、跟這一發 init 事件對得上的那幾個檔；刪 0 個或刪失敗會在主控台警告）。

實測（送一句帶獨特暗號的話，生完 grep 整個資料夾）：清完後暗號只剩在兩個共用摘要檔 `conversation_summaries.db`、`jetbox_summaries_proto.pb`；角色卡與歷史（在代理檔裡）沒有留。這兩個檔是 agy 所有對話共用的，改壞了會傷到使用者自己的 agy，所以橋不碰，README 照實寫。`history.jsonl` 只記互動模式的指令，print 模式不寫。`--log-file` 指到橋自己的暫存夾，生完就刪。

## 工具真的關乾淨了嗎

每一發開場事件仍會列出約 60 個工具名，但輸入 token 數顯示工具說明沒有送給模型。三道保險：代理檔 `tools: []`、`--sandbox`、無人值守模式下需要權限的動作一律自動拒絕。橋看到對話以外的步驟或被拒動作會在主控台記警告。刁難測試（要求建檔、跑指令）時模型用角色口吻拒絕，工作夾前後零變動。

## 讓位與並行

酒館按重新生成時，前一則還在生——要的是換一則，不是排隊。橋用「角色卡＋預設的開頭」加「對話第一則」算出一把對話鑰匙：同一把鑰匙的新請求會停掉舊的（舊的串流以 `finish_reason: length` 收尾，還沒出字的回 409）；不同對話可以同時跑，上限 `maxConcurrent`。斷線後同題再來的請求，會先登記成這段對話目前的請求再去等斷線那則，所以第三個請求還能把它們一起取消。

## 擋本機網頁

沒設金鑰的本機接口，任何網頁都能用 `fetch` 對 `127.0.0.1:5499` 送「簡單請求」（`text/plain` 不會觸發預檢）。橋的 POST 只收 `application/json`（逼瀏覽器先預檢，而橋從不回 CORS 許可），綁本機時 Host 標頭只接受本機名稱（擋 DNS 重綁定）。`host` 改成非本機位址又沒設 `apiKey` 時拒絕啟動。

## 代理檔頭

檔頭兩條 `---` 之間沒有任何來自請求的字：名字是十六進位、描述是固定字串，角色卡永遠在第二條 `---` 之後，而且正文第一行固定是一行標記（不是 `---`），所以就算角色卡以假的檔頭開頭，也不可能被當成第二份設定。角色卡裡的 `@路徑` 實測不會被 agy 展開。
