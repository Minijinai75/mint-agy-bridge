# 設計筆記

這份記下薄荷橋每個設計選擇背後的實測。數字都來自 agy 1.4.2、Windows 11，2026-10-19。

## 為什麼走官方 CLI，不走反向代理

市面上有把 Antigravity 帳號轉成 API 的反向代理，做法是冒充編輯器端、走編輯器內部的接口。薄荷橋只呼叫 Google 自己發的 `agy` 程式，跟你在終端機打字是同一條路。

## 角色卡怎麼送進去

agy 可以用 Markdown 檔定義自訂代理（`<工作夾>/.agents/agents/<名字>.md`，上半是設定、下半是系統提示），開跑時用 `--agent <名字>` 指定。橋每一則產生一個：

```
excludeDefaultComponents: true   # 拿掉 agy 內建那套寫程式的提示與工具
inheritCustomizations: false     # 不吃你全域的 GEMINI.md 規則
inheritMcp: false
tools: []
```

效果：同樣一句「早安」，預設代理的輸入約 11,900 token，自訂代理約 1,560 token（兩發的模型與題目不同，只能看量級）。從標準輸入送 `system` 事件，agy 明說不支援、會忽略，所以系統提示只能寫成代理檔。

## 為什麼歷史放代理檔、不放使用者訊息

實測一則 25 萬位元組、暗號放在最尾端的使用者訊息：模型回答「最後一行我看不到」。agy 在約 192,000 位元組處把使用者訊息切掉、塞一句「內容太長已截斷」，結果狀態**照樣是 SUCCESS**。同一份東西寫進代理檔，39 萬位元組（約 17 萬 token）頭尾暗號都答對。

所以橋的排法是：角色卡＋預設＋整段歷史進代理檔，標準輸入只送最新一則；最新一則超過 18 萬位元組時，整則挪進代理檔的 `<latest_message>`，標準輸入改送一句指路。正式版實測：25 萬位元組的最新一則，尾端暗號與最後一筆編號都答對。

命令列也不能塞（Windows 上限約 3.2 萬字元）。

## 為什麼每則開一個程序

| 跑法 | 首字中位數（Sonnet 4.6 短對話） |
|---|---|
| 每則開新程序 | 約 5.5 秒 |
| 每則開新程序、`--conversation` 續同一對話 | 約 5.7 秒（不會比較快） |
| 一個程序常駐連發 | 約 2.1 秒 |

慢的是開程序（2.5～4.7 秒），不是模型。常駐最快，但一個程序只能往後接，酒館的重新生成、編輯舊訊息都需要倒回去，agy 沒有倒帶。第一版選每則無狀態；常駐模式（偵測到「只在最後加一則」才走）列在之後。

另一個不續對話的理由：續對話時網路斷過一次，之後每一發明明有正常回覆，結果狀態都黏著 ERROR。橋判斷成敗看的是「模型回應步驟完成而且有字」，不信總狀態。

## 429 與重試

agy 遇到 429 會自己重試約 140 秒才放棄（exit code 3，stderr 一行 `AGY_ERROR: {...}`）。環境變數 `AGY_CLI_MODEL_API_MAX_RETRIES=0` 實測 8 秒就回，錯誤裡帶 `retryable:false`。橋預設 0，想讓 agy 多撐幾次就調 `maxRetries`。

## 本機留下的東西

每一發 agy 會在 `~/.gemini/antigravity-cli/` 留下：`conversations/<對話ID>.db`（約 400 KB）、`brain/<對話ID>/`（含完整逐字稿）、`annotations/<對話ID>.pbtxt`、`presence/<對話ID>.lock`。橋生完就刪這四樣（只刪 UUID 格式、跟這一發對得上的那幾個檔）。共用的摘要庫 `conversation_summaries.db` 橋不碰。

## 工具真的關乾淨了嗎

每一發開場事件仍會列出約 60 個工具名，但輸入 token 數顯示工具說明沒有送給模型。三道保險：代理檔 `tools: []`、`--sandbox`、無人值守模式下需要權限的動作一律自動拒絕。橋看到對話以外的步驟或被拒動作會在主控台記警告。刁難測試（要求建檔、跑指令）時模型用角色口吻拒絕，工作夾前後零變動。
